# sandboxed-agents v0.1.1 (preview)

Preview of the standalone executable
([#36](https://github.com/grauzone-git/sandboxed-ai-agents/issues/36)) that
replaces the unpublished `v0.1.0` and fixes its NuGet package
([#49](https://github.com/grauzone-git/sandboxed-ai-agents/issues/49)). Not a
stable release: the checkout launchers remain the supported entry point until the
[handover gates](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.1/docs/HANDOVER.md#gates)
close. Commands are unchanged from the `v0.1.0`
[capabilities](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.1/docs/releases/v0.1.0.md#capabilities).

## Why v0.1.0 was not released

Release run [36137613923](https://github.com/grauzone-git/sandboxed-ai-agents/actions/runs/36137613923)
failed and published no GitHub release. The binary build and provenance jobs
passed. Windows packaging failed in `nuget pack` with NU5030, because the
`LICENSE` file declared in the nuspec was not in the package. The `v0.1.0` tag
stays on `862cba0` and is not moved.

Diagnostic probes with NuGet 7.9 on Windows found the cause. With license
validation removed, probe run
[36138748828](https://github.com/grauzone-git/sandboxed-ai-agents/actions/runs/36138748828)
failed with NU5039 for the declared `README.md`. The release run did not reach
that error. A probe with both validations removed showed that the nuspec source
`tools/**` stored the payload at `tools/tools/*` in the package ZIP.

## Fix

- `packaging/prepare.py` writes the source as `tools\**`, which stores the
  payload at `tools/`. This is a one-line change.
- `tests/test-packages.py` runs a real `nuget pack`, requires exactly the seven
  expected `tools/` paths, and compares their bytes with the staged files.
  Against the original `prepare.py` it failed in run
  [36138528010](https://github.com/grauzone-git/sandboxed-ai-agents/actions/runs/36138528010).
  With the fix it passed on Windows with NuGet 7.9 in run
  [36138933498](https://github.com/grauzone-git/sandboxed-ai-agents/actions/runs/36138933498),
  and the version with the exact path check passed in run
  [36139491136](https://github.com/grauzone-git/sandboxed-ai-agents/actions/runs/36139491136).
  The full offline suite also passed with the exact path check.
- Regular CI installs the NuGet CLI on Windows, where the test requires it.

## Assets

- `sandboxed-agents-linux-amd64`, `sandboxed-agents-linux-arm64`,

[Installation](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.1/docs/RELEASES.md#install-a-downloaded-binary)

## Omitted commands

None. Every command listed in `sandboxed-agents --help` is implemented:
`version`, `build`, `list`, `update --all`, `adopt --all`, and, per sandbox,
`up`, `start`, `stop`, `restart`, `remove`, `shell`, `ssh-config`, `check`,
`check-full`, `fingerprint`, `agents`, `tools`, `run`, `tool`, `service`,
`forward`, `update`, `adopt`, and the session shortcuts.

## Not yet validated

These notes predate regular CI on the tagged commit (required for tagging and
recorded in [#50](https://github.com/grauzone-git/sandboxed-ai-agents/issues/50))
and the `v0.1.1` release workflow run, so they record neither result. `v0.1.1`
is not yet published. The owner has reported Linux host prerequisites only; no
real runtime check has run. Still open:

- Real rootless Podman runtime on [Linux](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.1/docs/HANDOVER.md#linux-procedure)
  and [Windows 11 with WSL2](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.1/docs/HANDOVER.md#windows-procedure)
- `adopt` of real checkout-owned sandboxes
- `service`, `forward`, and real Azure browser sign-in
- [Installation from the published release](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.1/docs/HANDOVER.md#packages-path-and-provenance):
  direct binary, npm, and NuGet, plus `gh attestation verify` and a rebuild
  reproducing `SHA256SUMS`
- The Linux ARM64 binary on an ARM64 host
- The NuGet user `PATH` change seen from a new terminal

## Known limitations

Unchanged from `v0.1.0`: Linux needs rootless Podman 5+ with the prerequisites
above; Windows needs Windows 11 x64 and Podman 6.0+. Only the three binaries are
attested, the Windows executable is not Authenticode-signed, packages are not
on npm or nuget.org, and there is no self-update command.
