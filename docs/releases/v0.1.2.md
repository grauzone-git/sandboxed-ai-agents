# sandboxed-agents v0.1.2 (preview)

Preview of the standalone executable
([#36](https://github.com/grauzone-git/sandboxed-ai-agents/issues/36)). It
replaces the unpublished `v0.1.1` and fixes the Linux npm install step of the
release workflow
([#49](https://github.com/grauzone-git/sandboxed-ai-agents/issues/49)). It is
not a stable release. The checkout launchers remain the supported entry point
until the
[handover gates](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.2/docs/HANDOVER.md#gates)
close. No runtime code changed since `v0.1.1`, and commands are unchanged from
the `v0.1.0`
[capabilities](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.2/docs/releases/v0.1.0.md#capabilities).

## Why v0.1.1 was not released

Release run [36140924527](https://github.com/grauzone-git/sandboxed-ai-agents/actions/runs/36140924527)
failed and published no GitHub release. The binary build, reproducibility, and
provenance jobs passed. On Windows, npm and NuGet packing, the package checksum
tests, and installs of both packages from outside the checkout passed.

The Linux npm job failed. It passed `packed/*.tgz` to `npm install`, and npm
read that argument as GitHub shorthand for a repository. npm then ran
`git ls-remote ssh://git@github.com/packed/sandboxed-agents-0.1.1.tgz.git`,
which exited with code 128. The `v0.1.1` tag stays on `3b4fcd4` and is not
moved.

The [v0.1.1 notes](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.2/docs/releases/v0.1.1.md#why-v010-was-not-released)
describe the earlier `v0.1.0` failure. The `v0.1.0` tag stays on `862cba0`.

## Fix

- The Linux npm install step in `.github/workflows/release.yml` passes
  `./packed/*.tgz`, which npm reads as a local path. This is a one-line change.

A targeted local check used the `release-packages` artifact downloaded from run
36140924527 and a local npm CLI. Both probes set `GIT_SSH_COMMAND=/bin/false`,
so git could not reach GitHub over SSH, and `--offline` kept npm off the
registry. With the existing `packed/*.tgz` argument, npm read it as the same
GitHub shorthand and exited with code 128. With `./packed/*.tgz`, the install
exited with code 0, the installed command reported version `0.1.1` from commit
`3b4fcd4`, and the package held the expected assets. npm ran the package's
`postinstall` script (`node install.cjs`), which exited with code 0. No live
containers were involved. The full offline
test suite (`./tests/run`) passed locally on this change, and source, link, and
diff checks pass. Regular CI on the new candidate commit and the `v0.1.2`
release workflow have not yet run.

## Omitted commands

None. Every command listed in `sandboxed-agents --help` is implemented:
`version`, `build`, `list`, `update --all`, `adopt --all`, and, per sandbox,
`up`, `start`, `stop`, `restart`, `remove`, `shell`, `ssh-config`, `check`,
`check-full`, `fingerprint`, `agents`, `tools`, `run`, `tool`, `service`,
`forward`, `update`, `adopt`, and the session shortcuts.

## Not yet validated

These notes predate regular CI on the tagged commit (required for tagging and
recorded in
[#50](https://github.com/grauzone-git/sandboxed-ai-agents/issues/50)) and the
`v0.1.2` release workflow run, so they record neither result. `v0.1.2`
is not yet published. The owner has reported Linux host prerequisites only, and
no real runtime check has run. Still open:

- Real rootless Podman runtime on [Linux](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.2/docs/HANDOVER.md#linux-procedure)
  and [Windows 11 with WSL2](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.2/docs/HANDOVER.md#windows-procedure)
- `adopt` of real checkout-owned sandboxes
- `service`, `forward`, and real Azure browser sign-in
- [Installation from the published release](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.2/docs/HANDOVER.md#packages-path-and-provenance):
  direct binary, npm, and NuGet, plus `gh attestation verify` and a rebuild
  reproducing the published `SHA256SUMS`
- The Linux ARM64 binary on an ARM64 host
- The NuGet user `PATH` change seen from a new terminal

## Known limitations

These are unchanged from `v0.1.0`. Linux needs rootless Podman 5+ with the host
prerequisites linked above, and Windows needs Windows 11 x64 and Podman 6.0+.
Only the three binaries are attested, the Windows executable is not
Authenticode-signed, packages are not on npm or nuget.org, and there is no
self-update command.
