# sandboxed-agents v0.1.0 (preview)

First preview of the standalone `sandboxed-agents` executable
([#36](https://github.com/grauzone-git/sandboxed-ai-agents/issues/36),
[#50](https://github.com/grauzone-git/sandboxed-ai-agents/issues/50)). This is
not a stable release. The checkout launchers (`./sandbox`, `sandbox.ps1`)
remain the supported entry point until the gates in
[HANDOVER.md](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.0/docs/HANDOVER.md#gates)
close.

## Assets

- `sandboxed-agents-linux-amd64`, `sandboxed-agents-linux-arm64`,
  `sandboxed-agents-windows-amd64.exe`
- `SHA256SUMS` for the three binaries
- `sandboxed-agents-0.1.0.tgz` (npm, all three binaries)
- `SandboxedAgents.0.1.0.nupkg` (NuGet, Windows binary)

## Capabilities

- `version`, `build`, and `list`, with the container build context bundled in
  the binary
- Sandbox lifecycle: `up`, `start`, `stop`, `restart`, `remove`, `shell`,
  `check`, `check-full`, with named volumes or a bound workspace directory,
  controller-group ownership, and workspace protection
- Opt-in SSH: `up --ssh-config`, `ssh-config`, `fingerprint`, with pinned host
  keys and managed `Include`
- Nested Podman with `--capabilities podman` on Linux and Windows
- Agent and tool management, logins, `run`, `tool`, and session shortcuts
- `service`, `forward`, and `tools setup` for T3, Azure DevOps, and Azure,
  including host browser sign-in with `--interactive`
- Transactional image `update` and `update --all`, with rollback
- Explicit adoption of checkout-owned sandboxes with `adopt --from` and
  `adopt --all --from`, including SSH migration; see
  [Adopt checkout-owned sandboxes](https://github.com/grauzone-git/sandboxed-ai-agents/blob/v0.1.0/docs/EXECUTABLE.md#adopt-checkout-owned-sandboxes)
- Windows 11 x64 support through an existing rootless Podman 6 WSL2 machine

## Omitted commands

None. Every command listed in `sandboxed-agents --help` is implemented:
`version`, `build`, `list`, `update --all`, `adopt --all`, and, per sandbox,
`up`, `start`, `stop`, `restart`, `remove`, `shell`, `ssh-config`, `check`,
`check-full`, `fingerprint`, `agents`, `tools`, `run`, `tool`, `service`,
`forward`, `update`, `adopt`, and the session shortcuts. The executable remains
a preview.

## Known limitations

- Linux needs rootless Podman 5 or newer with subordinate ID ranges, `pasta`,
  and delegated cgroups v2 controllers; the executable does not check these
  beforehand.
- Windows needs Windows 11 x64 and Podman 6.0 or later; ARM64 Windows is not
  supported.
- Only the three binaries are attested. `SHA256SUMS` and the package files are
  not.
- The Windows executable is not Authenticode-signed.
- Packages are not published to npm or nuget.org.
- There is no self-update command.
